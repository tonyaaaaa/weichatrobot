# 自动长期记忆运营手册

## 运行边界

- MySQL 是候选、观察、正式记忆、状态、版本和审计的权威来源。
- Qdrant 的 `memory_{distance}_{dimension}_g{generation}` 集合只保存检索向量和最小元数据，不保存记忆正文。
- 业务知识集合与记忆集合严格分离。行为记忆不能作为业务事实证据。
- `BusinessFact` 只进入“知识学习审核”，管理员批准并选择知识标签后才进入知识索引。
- 第一阶段用户作用域由机器人、群和规范化昵称组成，不代表稳定企业微信身份。

## 自动整理时机

- 消息包含“记住”时，正常回复提交后立即创建 `ExtractConversationMemory` 任务。
- 其他已回复消息在会话空闲 30 分钟后整理。
- 整理使用当前启用的默认 Chat 模型，不需要单独的记忆模型。
- 候选写入具备消息级幂等约束；重复回调和任务重试不会重复累计同一条证据。

## 晋升规则

- 明确的行为记忆：可信度至少 `0.80`，可直接晋升。
- 普通行为记忆：可信度至少 `0.80`、至少 3 个不同会话、至少 2 个 UTC 自然日。
- 未解决冲突不晋升。
- `BusinessFact` 永不自动晋升为行为记忆。

## 记忆中心

- “待整理”：查看作用域、类型、可信度、证据次数、不同会话/日期数；支持编辑、晋升和拒绝。
- “长期记忆”：查看有效期、召回次数和状态；支持忘记和恢复。
- “整理任务”：查看等待、执行、重试和失败状态；失败任务可受控重试。

所有修改使用版本并发控制。收到 `409` 时刷新列表后重新操作。

## 故障处理

- 默认 Chat 模型不可用：整理任务进入重试，超过上限进入死信；不影响正常回复。
- Embedding 或 Qdrant 不可用：记忆索引/召回返回稳定失败码；知识检索和正常回答继续运行。
- 群停用或归档：Worker 在执行前复查群状态，不整理该群的新记忆。
- 忘记、替代或过期：MySQL 状态立即生效；即使 Qdrant 删除暂时失败，召回后仍会通过 MySQL 校验过滤。

## 发布后检查

1. 确认 API、Worker 和前端使用同一份生产环境配置。
2. 确认默认 Chat 和 Embedding 模型均已启用并通过连接测试。
3. 确认 Worker 心跳正常，且没有持续增长的记忆死信。
4. 在测试群发送“请记住我偏好结论优先”，确认正常回复不被整理任务阻塞。
5. 在记忆中心确认候选、晋升任务和长期记忆状态。
6. 提交一条业务事实，确认只出现在知识学习审核，未批准前不会进入知识 Qdrant。
7. 临时阻断 Qdrant，确认知识问答仍能按既有失败策略返回，恢复后可重试索引任务。

## 安全检查

- 不在任务 payload、审计或 API 中保存完整模型输入/输出、密钥、验证码、连接字符串或上游原始响应。
- 记忆审计只保存 ID、作用域、类型、版本、分数和稳定失败码。
- 生产 `.env` 不放在网站目录，不提交版本库。
