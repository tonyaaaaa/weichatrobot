# 管理后台页面完整性检查清单

## 判定规则

- `完整`：现有页面已经连接真实 API，主要工作流闭环，并具有可识别的加载、
  空数据和失败状态。保持现有设计，不进行无必要重做。
- `合同阻塞`：缺少真实后端合同，前端不得制作假表单或假数据。
- 浏览器视觉验收在本轮最终验证后补充运行证据；没有视觉证据时不以“样式旧”
  作为重构理由。

## 保持不变的原则

- 原生控件本身不是缺陷；只有操作阻塞、可访问性、状态缺失或溢出时才局部修改。
- 自制布局本身不是缺陷；已经闭环的页面不为统一外观而重写。
- 系统设置在真实 API 出现前保持只读边界，不能声称可配置。
- WorkTool 群名和成员显示名继续按观察值处理，不冒充稳定身份。

## 最终验收记录

- 前端 50 个测试文件、159 个测试已覆盖现有页面工作流与本轮群配置改动。
- TypeScript/Vue 类型检查及生产构建通过。
- 群配置内存数据库与 MySQL 集成测试共 13 个通过。
- 登录页可在本地运行时正常打开；本轮没有可使用的管理后台登录态，因此未把
  1440、768、375 三种登录后页面的浏览器截图冒充为已完成验收。
- 后续取得测试登录态时，仅补视觉核验；不得据此重新设计已经闭环的页面。
