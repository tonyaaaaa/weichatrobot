# 记忆整理任务与通用群名称选择器设计

## 背景

记忆中心的“整理任务”页签当前请求
`GET /api/admin/memory/jobs` 时返回服务器错误。真实 MySQL 日志表明，
MySQL EF Core Provider 无法为局部字符串数组参与的
`types.Contains(x.JobType)` 表达式分配类型映射。

记忆中心的群筛选当前使用 UUID 文本输入。用户从群管理页面进入记忆中心时，
路由会携带 `groupId`，页面直接展示 UUID，无法从界面判断对应群名称。
会话审计已经提供群名称下拉，但实现局限在审计模块，尚未形成可复用的群选项契约。

## 目标

1. 修复记忆整理任务列表在 MySQL 5.7 上的查询失败。
2. 管理页面不再要求用户手填或识别群 UUID。
3. 建立独立、通用的群选项 API 和 Vue 选择器组件。
4. 会话审计和记忆中心使用同一套群名称展示和选择规则。
5. 后端筛选仍使用稳定的 `GroupProfile.Id`，不使用群名称作为关联键。

## 非目标

- 不从 WorkTool 实时群列表构建筛选选项。
- 不使用群名称或群备注替代本地 `GroupProfile.Id`。
- 不改变群同步、群登记或群成员逻辑。
- 不在本任务中修改记忆提取、晋升、召回或索引规则。
- 不把群选项接口限制为 WorkTool 管理员专用接口。

## 后端设计

### 通用群选项 API

新增：

```text
GET /api/group-options
```

接口要求已认证用户，并允许当前需要群筛选的管理角色访问。返回本地已登记群，
不调用 WorkTool 外部接口。

每个选项包含：

```text
id
name
workToolGroupRemark
robotName
state
isEnabled
```

列表按群名称和 ID 稳定排序，并包括已启用、已停用和已归档群，确保历史审计、
历史记忆和从群管理页带入的路由参数仍可解析为名称。

现有 `/api/audit/group-options` 改为调用同一查询服务，或在前端迁移完成后保留兼容
入口但不再维护第二套查询逻辑。通用查询行为必须只有一个来源。

### 整理任务查询

记忆任务类型保持以下四类：

- `ExtractConversationMemory`
- `MaintainLongTermMemory`
- `IndexMemoryEntry`
- `RemoveMemoryEntryFromIndex`

查询不能继续使用 MySQL Provider 无法翻译的局部数组 `Contains`。改为可直接映射的
显式等值逻辑，或使用仓库已有的数据库兼容查询辅助方式。筛选、计数、排序和分页仍在
数据库执行，不能退化为先加载全部任务再在内存过滤。

## 前端设计

### 共享组件

新增共享组件 `GroupProfileSelect.vue`。

组件职责：

- 加载通用群选项。
- `v-model` 保存群 UUID。
- 下拉主文案显示群名称。
- 补充显示群备注、机器人名称和状态。
- 支持输入筛选、清空为“全部群”。
- 支持由路由传入 UUID 后自动显示对应群名称。
- 加载期间禁用选择并显示加载状态。
- 加载失败时向页面暴露明确错误，不退化成 UUID 文本框。

建议文案格式：

```text
技术支持群（support-east） · 默认机器人
售后群 · 默认机器人 · 已停用
历史群 · 默认机器人 · 已归档
```

组件必须具有可访问标签、键盘操作能力和稳定的空状态文案。

### 页面接入

记忆中心三个页签共用同一个群名称选择器：

- 待整理
- 长期记忆
- 整理任务

切换页签保留当前群选择，重置状态筛选和页码。选择群后仍向记忆 API 发送
`groupProfileId`。

会话审计改用同一共享选择器，并继续向审计 API 发送 `groupId`。原错误文案
“请检查群 ID”改为面向用户的“请检查群筛选和时间范围”。

扫描结果中，其他群操作页面使用的是 WorkTool 群名称或本地已登记群选择，
不属于 UUID 手填筛选，本任务不改变其业务语义。

## 权限与数据来源

群选项来源必须是本地 `GroupProfile` 与 `RobotConfig` 的关联数据。
不得使用 WorkTool 的已废弃群列表作为后台选择器事实来源。

通用接口只返回展示所需的非秘密字段，不返回机器人标识、回调密钥、模型密钥或
其他凭据。KnowledgeOperator 能访问记忆中心和会话审计，因此不能依赖仅允许 Admin
访问的 `/api/admin/worktool/groups`。

## 错误处理

- 群选项加载失败：页面显示“群列表加载失败，请重试”，保持筛选区可理解。
- 记忆数据加载失败：保留当前明确错误和重试按钮。
- 已选择的群后来被停用或归档：仍显示名称和状态，允许查询历史数据。
- 路由携带不存在的群 ID：选择器显示“群记录不存在或已删除”，不显示裸 UUID，
  页面查询可以返回空结果。
- 整理任务查询失败：API 返回标准问题响应，前端不伪造空列表。

## 测试与验收

### 后端

- 真实 MySQL 集成测试覆盖 `/api/admin/memory/jobs`，验证四类任务可查询且其他任务
  不会混入。
- 通用群选项 API 测试覆盖权限、排序、启用/停用/归档状态和机器人名称。
- 现有会话审计群选项契约保持兼容。

### 前端

- 共享选择器测试覆盖加载、搜索、选择、清空、失败、停用和归档标识。
- 记忆中心测试确认界面不再出现“群 ID”文本输入，选择后发送正确
  `groupProfileId`。
- 路由传入群 ID 时显示对应群名称。
- 会话审计测试确认使用共享选择器并发送正确 `groupId`。
- 前端类型检查、完整 Vitest 和生产构建通过。

### 本地运行

- `GET /api/admin/memory/jobs?page=1&pageSize=20` 返回 HTTP 200。
- 记忆中心三个页签都能按群名称筛选。
- 会话审计能按同一群名称选择器筛选。
- API、Worker、前端保持运行，readiness 中 MySQL、Qdrant、OCR、OSS 和 Worker
  心跳均为健康。
