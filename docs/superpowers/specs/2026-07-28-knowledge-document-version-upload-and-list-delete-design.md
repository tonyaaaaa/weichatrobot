# 知识文档新版本上传与列表删除设计

## 目标

补齐已有后端能力在管理端的操作入口：

- 从文档详情页为当前 `documentId` 上传新版本。
- 从文档列表直接提交物理删除请求。
- 保留现有详情页版本历史、版本详情和物理删除入口。

## API 契约

`KnowledgeApi.upload` 增加可选的第三个参数：

```ts
upload(
  file: File,
  onProgress: (value: number) => void,
  documentId?: string
): Promise<UploadResult>
```

上传新文档时只提交 `file`。上传新版本时在同一个
`multipart/form-data` 请求中同时提交 `file` 和 `documentId`。不新增或伪造
后端路由。

## 文档详情页

在文档状态与版本历史之间增加“上传新版本”区域：

- 文件选择使用现有允许格式说明和上传进度反馈。
- 提交时调用 `upload(file, onProgress, 当前文档 ID)`。
- 上传成功后清空选择、显示成功消息，并重新加载详情和版本历史。
- 文档状态为 `disabled` 或 `delete-requested` 时隐藏上传表单，并说明不可上传。
- 上传中禁用文件选择和提交按钮，避免重复提交。
- 上传失败使用稳定的中文失败提示，不显示后端异常或敏感响应正文。

## 文档列表

每行操作区增加“提交物理删除”：

- 仅 `Admin` 角色可见；`KnowledgeOperator` 不显示该入口。
- 使用行内 `id` 和 `stateVersion` 调用现有 `requestPhysicalDelete`。
- 使用与详情页一致的确认文案：
  `这会停用文档并提交异步物理清理，期间不可上传新版本。确认继续？`
- 成功后显示“删除请求已受理，等待后台清理”，并刷新当前列表。
- `document-concurrency-conflict` 时合并服务端当前状态并提示页面已更新。
- `document-delete-requested` 时提示已提交删除请求。
- 其他失败只显示稳定的操作失败提示。
- 删除请求执行中只禁用对应行按钮。

## 权限与安全

- 前端角色判断仅用于控制操作入口；后端 Admin 授权仍是最终权限边界。
- 不在前端展示对象存储键、暂存内容、上游响应体或其他敏感字段。
- 不更改详情页既有的 Admin 物理删除入口。

## 验证

- API 测试证明普通上传不携带 `documentId`，新版本上传携带准确的
  `documentId`。
- 详情页组件测试证明新版本上传参数、进度/忙碌状态、成功刷新和禁用状态。
- 列表页组件测试证明 Admin 可见、非 Admin 不可见、确认后使用行状态版本、
  成功刷新，以及并发和重复删除错误处理。
- 运行前端定向测试、完整 Vitest、TypeScript 类型检查和生产构建。
- 使用本地页面检查操作入口、按钮忙碌态、移动端无横向破坏；若运行环境不可用，
  明确报告未完成的运行时验收。
