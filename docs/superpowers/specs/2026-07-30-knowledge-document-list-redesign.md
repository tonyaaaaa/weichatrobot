# 知识文档列表来源与知识库绑定展示设计

日期：2026-07-30
状态：已批准
范围：知识文档管理列表、对应查询 API 与前端筛选；不改变知识写入、审核、
索引或检索语义。

## 1. 背景

当前知识文档页面已经具备上传、分页列表、详情、失败上传重试和受控物理删除，
但列表只显示文档状态、最新版本和失败摘要。运营人员无法直接判断：

- 文档当前绑定了哪些知识库标签。
- 当前生效知识来自文档上传、消息审核、私聊直接入库还是历史数据。
- 如何按知识库标签或来源筛选文档。

页面顶部长期展开上传表单，也削弱了列表作为日常运营入口的视觉优先级。

本设计采用已选定的 A 方案“信息密集管理表格”，在保留全部真实操作能力的
前提下补齐权威数据和筛选契约。

## 2. 设计原则

- 数据库和现有索引关系是权威来源，不根据标题、文件名或显示名称推断标签。
- 知识来源按文档版本记录；列表展示当前有效版本的来源。
- 不新增虚构的 `KnowledgeBase` 实体；页面中的“绑定知识库”指现有
  `KnowledgeTag`。
- 不把无标签记录伪装成“全局知识”。只有真实绑定系统全局知识标签时才显示
  “全局知识”；异常或尚未绑定的记录显示“未绑定”。
- 保留现有详情、失败重试、权限、乐观并发和受控物理删除语义。
- 本功能不新增数据库表或迁移。

## 3. 当前有效版本规则

列表为每个文档确定一个 `effectiveVersion`：

1. `KnowledgeDocument.ActiveVersionId` 存在时，使用该版本。
2. 没有活动版本时，使用版本号最大的最新版本。
3. 文档没有任何版本时，有效版本为空。

来源、来源显示名称和绑定知识库标签全部基于同一个有效版本，避免来源取最新
版本、标签却取活动版本造成同一行含义漂移。

详情页继续返回完整版本历史，不受该列表规则限制。

## 4. 绑定知识库规则

绑定关系来自有效版本下已持久化分段的 `KnowledgeChunkTag`：

```text
KnowledgeDocument
  -> effective KnowledgeDocumentVersion
  -> KnowledgeChunk
  -> KnowledgeChunkTag
  -> KnowledgeTag
```

列表返回去重后的标签 ID 和名称，按标签名称、ID 稳定排序。

- 系统全局知识标签如果真实绑定，正常返回并显示“全局知识”。
- 没有任何绑定时返回空数组，前端显示“未绑定”。
- 列表保留已经绑定但后来被停用的标签名称，以准确解释现有索引数据。
- 筛选标签时按标签 ID 精确匹配有效版本的真实绑定。

## 5. 来源规则

来源读取有效版本的 `KnowledgeDocumentVersion.SourceKind`：

| 后端值 | 前端显示 |
|---|---|
| `DocumentUpload` | 文档上传 |
| `ConversationReview` | 消息审核入库 |
| `PrivateChatDirect` | 私聊直接入库 |
| `LegacyUnknown` 或未知兼容值 | 历史数据 |

`SourceActorDisplayName` 非空时作为来源补充信息显示。它只用于运营说明，不
作为稳定身份标识或权限依据。

## 6. API 契约

扩展现有接口：

```http
GET /api/knowledge/documents
```

查询参数：

- `query`：文档标题模糊搜索。
- `status`：文档持久化状态精确筛选。
- `sourceKind`：有效版本来源精确筛选。
- `tagId`：有效版本绑定知识标签精确筛选。
- `page`、`pageSize`：现有分页规则，页码最小 1，页大小最大 100。

`KnowledgeDocumentSummary` 新增：

- `sourceKind`
- `sourceActorDisplayName`
- `tags: [{ id, name }]`

`KnowledgeDocumentVersionSummary` 同样新增：

- `tags: [{ id, name }]`

版本标签必须来自该版本下分段的真实 `KnowledgeChunkTag` 绑定，不只返回文档
当前有效版本标签。分段与索引页面使用版本标签作为选择器初始值。

现有字段保持兼容。筛选必须在数据库分页和 `Total` 统计之前执行，不能只过滤
当前页。查询保持有界，并增加 MySQL 5.7 翻译测试。

## 7. 前端布局

### 7.1 页面头部

- 标题和说明保持简洁。
- 右上角提供主按钮“上传文档”。
- 点击后打开 Element Plus 弹框，承载现有文件选择、旧版 `.doc` 提示、上传
  进度、成功和失败状态。
- 上传成功后关闭弹框并刷新列表；失败时保留弹框和错误信息，便于重试。

### 7.2 筛选栏

筛选栏依次提供：

- 文档名称。
- 绑定知识库。
- 来源。
- 状态。
- “查询”和“重置”操作。

知识库选项复用现有知识标签 options API，不允许手填 UUID。标签选项加载失败
不阻塞文档列表，页面显示可重试的筛选提示。

筛选条件变更后由用户点击查询，避免每次键入都请求 API；重置清空全部条件并
回到第一页。

### 7.3 管理表格

桌面端列为：

1. 文档：标题、版本数量和当前版本。
2. 绑定知识库：标签徽标，超过可用宽度时换行；空数组显示“未绑定”。
3. 来源：中文来源徽标和可选来源显示名称。
4. 状态：中文状态、最新版本状态和脱敏失败摘要。
5. 更新时间。
6. 操作：详情、失败重试、管理员受控物理删除。

失败摘要合并到状态列，移除独立宽列，减少横向空间。

状态使用可理解的中文文本，不改变后端持久化状态值。

### 7.4 窄屏

桌面表格在窄屏下切换为单列文档卡片，保留相同字段和操作，不要求用户横向
滚动才能完成核心操作。

### 7.5 文档详情按来源展示

文档详情页读取当前有效版本和全部历史版本的来源：

| 来源 | 详情页能力 |
|---|---|
| `DocumentUpload` | 显示文件、解析/OCR、版本历史；允许上传文件生成新版本 |
| `ConversationReview` | 显示消息审核来源、来源成员、知识内容与版本沿革；不提供文件覆盖上传 |
| `PrivateChatDirect` | 显示私聊直接入库、来源成员、批次、变更类型与被替代版本；不提供文件覆盖上传 |
| `LegacyUnknown` | 显示来源无法确认提示；为兼容历史数据保留现有管理能力 |

停用和管理员受控物理删除继续作为文档级操作保留。自动来源需要修正时，应从
消息审核或私聊直接入库链路创建新版本，不允许在详情页用文件覆盖来源历史。

每个版本卡片显示：

- 来源中文名称和可选来源成员。
- `New`、`Duplicate`、`Supplement`、`Correction` 的中文变更类型。
- 绑定知识库标签。
- `SupersedesVersionId` 存在时显示版本沿革提示。
- 文件、OCR 信息只在其真实存在且与该来源有意义时显示。

### 7.6 分段与索引按来源开放操作

版本页面加载版本详情后按 `SourceKind` 决定模式：

- `DocumentUpload`：保留重新生成、编辑、拆分、合并、删除和批准的完整分段
  流程。
- `ConversationReview`、`PrivateChatDirect`：标题改为“入库内容与索引”，分段
  正文只读，不显示或禁用重新生成、编辑、拆分、合并、删除和再次批准。
- `LegacyUnknown`：显示来源兼容提示，保留现有分段操作，避免历史数据失去
  管理入口。

所有来源都显示真实绑定知识库标签：

1. 页面加载后把当前版本 `tags[].id` 写入 `selectedTagIds`。
2. 已绑定知识库默认勾选。
3. 管理员可以调整标签后重新索引，包括自动来源。
4. 未绑定版本保持空选择，并在提交索引时要求至少选择一个启用标签。
5. 失败索引任务继续提供受控重试。

页面不得把标签 options API 的“全部启用标签”误认为当前版本已绑定标签。
options 只提供候选；版本详情中的 `tags` 才是初始选中真相。

## 8. 状态与失败处理

- 初始加载显示骨架。
- 无结果显示与当前筛选一致的空状态。
- 文档列表失败显示重试入口。
- 标签选项失败与文档列表失败分开处理。
- 上传、重试和删除继续显示现有成功、冲突和失败反馈。
- 乐观并发冲突继续把服务器当前状态合并到对应行。
- 来源或标签数据缺失时显示兼容文本，不让整个列表加载失败。

## 9. Element Plus 完整性

新增或引用 `ElDialog`、`ElSelect`、`ElOption` 等组件时必须同时完成：

1. Vue 逻辑导入。
2. `main.ts` 中对应独立样式入口导入。
3. 样式依赖回归测试。
4. 浏览器视觉检查，确认弹框、选择器、表格和窄屏卡片没有无样式或溢出。

## 10. 测试与验收

### 后端

- 有活动版本时来源和标签取活动版本，不被更新的暂存版本覆盖。
- 无活动版本时取最新版本。
- 来源筛选作用于完整结果和 `Total`。
- 标签筛选作用于完整结果和 `Total`。
- 无标签返回空数组。
- 版本详情返回每个版本自己的标签绑定。
- 来源显示名称和失败原因保持脱敏边界。
- 查询在 MySQL 5.7 上可翻译执行。
- 端点接受 `sourceKind`、`tagId` 并返回新字段。

### 前端

- 初始请求包含新增的空筛选条件。
- 来源、标签和中文状态正确显示。
- 标签和来源筛选从第一页请求。
- 重置清空全部筛选。
- 上传表单只在弹框打开后显示。
- 上传成功刷新列表，失败保留错误。
- 详情、重试、删除权限和并发冲突回归通过。
- 文档详情按来源显示不同的来源证据和新版本能力。
- 自动来源不显示文件覆盖上传。
- 自动来源的分段正文只读，文档上传来源保留完整分段操作。
- 分段与索引页面默认勾选当前版本的真实标签。
- 调整自动来源标签后可以重新索引。
- Element Plus 组件样式依赖测试通过。

### 真实闭环

1. 通过私聊直接入库创建知识。
2. 文档列表按“私聊直接入库”筛选到该记录。
3. 验证来源显示名称与实际绑定知识标签。
4. 使用同一知识再次私聊提问。
5. 验证 Qdrant 检索命中并由机器人正常回复。

## 11. 非目标

- 不新增独立知识库实体。
- 不改变私聊入库标签匹配算法。
- 不在本列表编辑文档标签或版本内容。
- 不新增状态聚合统计 API。
- 不改变 Qdrant collection、索引或激活流程。

## 12. 已批准决策

- 采用 A 方案“信息密集管理表格”。
- 上传表单改为右上角按钮打开弹框。
- “绑定知识库”使用现有知识标签的真实绑定。
- 增加知识库标签、来源和状态筛选。
- 来源按当前有效版本展示。
- 保留全部现有文档管理操作。
- 文档详情和版本页面按来源开放不同能力。
- 消息审核和私聊直接入库的分段正文只读。
- 自动来源仍允许调整知识标签并重新索引。
- 已绑定知识标签进入版本页面时必须默认勾选。
