# 私聊知识入库 Agent 重复判定修复设计

## 背景

私聊知识入库 Agent 可以返回 `Duplicate`、`New`、`Supplement` 或
`Correction`。当前处理器只有在问题和答案都逐字相同时才认定重复。
如果 Agent 已返回 `Duplicate` 并给出有效的 `SimilarVersionId`，但答案
存在措辞差异，处理器会因为无法解析更新目标而把结果静默改为 `New`。

这会造成两个用户可见问题：

- 已被 Agent 判定为重复的知识仍创建新的活动文档。
- 批次统计和机器人通知把该条汇报为新增，而不是重复。

## 目标

- 重复与否由私聊知识入库 Agent 判断。
- 同一问题即使答案内容不同，也应由 Agent 判定为重复。
- 问题表述不同但语义相同，也应由 Agent 判定为重复。
- 服务端忠实执行合法的 `Duplicate` 结论，不再静默改写为 `New`。
- 服务端仍负责校验目标知识是否存在且当前有效，Agent 不直接写数据库。
- 重复项不创建文档、版本、分块或索引任务。
- 批次统计和最终通知准确汇报重复数量。

## 非目标

- 不使用固定向量相似度阈值替代 Agent 的语义判断。
- 不把所有“问题相同、答案不同”的内容在服务端强制判为重复。
- 不自动清理已经产生的历史重复文档。
- 不修改 `appsettings`、环境变量或数据库结构。

## 方案比较

### 方案 A：Agent 结论优先，服务端校验目标（采用）

Agent 基于相似知识检索判断问题语义，而不是比较问题或答案字符串。Agent
返回 `Duplicate` 和 `SimilarVersionId` 后，服务端确认该版本属于当前
活动文档；校验通过即按重复处理。校验失败时不得凭无效引用认定重复，而是
回退为新增，保证数据可追溯。

优点是职责清晰、改动小，并与现有 Agent 工具和提案结构一致。缺点是判重
质量依赖 Agent 检索与推理质量。

### 方案 B：服务端按相同问题强制判重

无论 Agent 结论如何，只要活动知识中存在相同问题就视为重复。

优点是规则确定；缺点是会吞掉 Agent 明确认定的补充或纠正，也不符合
“由 Agent 判断”的业务要求。

### 方案 C：服务端使用向量阈值自动判重

处理器再次检索并根据固定相似度阈值决定是否重复。

优点是能捕捉改写；缺点是存在误判、依赖外部检索状态，并形成第二套与
Agent 竞争的判定逻辑。

## 处理流程

1. Agent 通过 `find_similar_knowledge` 检索活动知识。
   `propose_knowledge_items` 必须以程序方式确认每个最终问题已经调用过该
   工具，不能只依赖提示词要求模型主动检索。
2. Agent 根据问题语义判断是否与已有知识重复：
   - 问题相同但答案不同，判定为 `Duplicate`。
   - 问题措辞不同但含义相同，判定为 `Duplicate`。
   - 只有知识事实发生补充或纠正时，才使用 `Supplement` 或
     `Correction`。
3. Agent 输出提案，其中包含 `ChangeKind` 和可选的
   `SimilarVersionId`；`Duplicate` 必须返回相似活动版本 ID。
   `Duplicate`、`Supplement` 和 `Correction` 的版本 ID 必须来自该问题
   本次 `find_similar_knowledge` 的返回结果，否则拒绝整次提交。
4. 处理器继续保留现有“问题和答案逐字相同”的确定性快速判重。
5. 若提案为 `Duplicate`：
   - `SimilarVersionId` 指向当前活动版本时，记录匹配文档、版本和标签，
     将该项标记为重复并停止后续发布。
   - 引用缺失、已停用、已被替换或与活动文档不一致时，不接受该重复结论，
     回退为新增。
6. `Supplement` 和 `Correction` 沿用现有目标校验与版本发布流程。
7. `New` 沿用现有新文档发布流程。
8. 批次重新计数时保留最终的 `Duplicate`，通知据此汇报重复数量。

## 边界与失败处理

- 只有当前活动文档的活动版本可作为重复目标。
- 无效的 Agent 引用不能阻断整批入库，也不能指向停用知识。
- 同批次幂等和已存在的逐字判重逻辑保持不变。
- 不记录问题、答案、模型响应或凭据等敏感原文到新增日志中。
- 本修复不对已有重复文档执行停用、删除或合并。

## 测试设计

新增集成回归测试，先在旧实现上确认失败：

1. 已存在一个活动知识版本。
2. 分别覆盖两种 Agent 提案：
   - 问题相同、答案不同，返回 `Duplicate` 和有效
     `SimilarVersionId`。
   - 问题表述不同但语义相同，返回 `Duplicate` 和有效
     `SimilarVersionId`。
3. 运行入库处理器。
4. 断言批次 `NewCount = 0`、`DuplicateCount = 1`。
5. 断言入库项保留匹配文档和版本。
6. 断言没有创建新知识文档、版本、分块和索引任务。

同时保留并运行既有新增、补充/纠正、原子激活和通知测试，防止修复改变
非重复路径。

新增 Agent 单元回归测试：

- 未调用 `find_similar_knowledge` 就直接提交 `New` 时拒绝提案。
- 提交的重复版本 ID 不在该问题的相似检索结果中时拒绝提案。
- 完成相似检索并提交其返回的版本 ID 时接受语义重复提案。

## 验收标准

- Agent 返回合法 `Duplicate` 时，不再创建第二份活动知识。
- 同题异答或问题改写但语义相同时，Agent 均可判定并汇报为重复。
- 批次详情和机器人通知均汇报一条重复、零条新增。
- Agent 返回无效目标时不会错误绑定停用或过期知识。
- 不新增配置或迁移。
- 聚焦回归测试、相关集成测试、编译和差异检查全部通过。
