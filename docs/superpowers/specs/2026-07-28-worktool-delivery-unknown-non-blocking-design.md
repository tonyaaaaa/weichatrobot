# WorkTool 发送结果不确定时的非阻塞设计

## 背景

Worker 调用 WorkTool 发送消息后，如果 HTTP 连接已经开始但没有取得可确认的
WorkTool 响应，系统会把发送命令标记为 `deliveryUnknown`。这能避免自动重试造成
重复消息，但当前租约查询把该状态视为同一机器人的前置命令，导致其后的所有消息
永久阻塞。

## 目标

- `deliveryUnknown` 不自动重试，继续防止重复发送。
- `deliveryUnknown` 不再阻塞同一机器人的后续发送命令。
- 后续可发送命令仍按创建时间和 ID 保持 FIFO。
- 保留不确定命令的状态、原因和时间，供运营核对。
- 提供发送队列分页查询和受控运营操作。
- 不改变 WorkTool 请求格式、发送限流、机器人发送门和已受理命令的结果等待逻辑。

## 状态语义

`deliveryUnknown` 是隔离终态：外部发送可能已经发生，但系统无法证明成功或失败。
Worker 不再租约或重试该命令，也不将其转换成成功或失败。

租约查询只把仍可能执行或恢复执行的早期命令视为 FIFO 屏障：

- `pending`
- `retrying`
- `leased`
- `dispatching`
- `blocked`

`deliveryUnknown` 不属于 FIFO 屏障。一个机器人存在该状态时，Worker 可以继续租约
其后最早的可发送命令。

新增两个运营终态：

- `cancelled`：管理员取消尚未发送的 `pending` 或 `retrying` 命令。
- `deliveryUnknownResolved`：管理员确认已核对结果不确定的命令。该状态不表示发送
  成功，也不会触发重发。

## 数据流

1. Worker 将命令标记为 `dispatching` 后调用 WorkTool。
2. 若取得有效的受理结果及消息 ID，命令进入 `accepted`。
3. 若明确被拒绝，命令进入现有拒绝状态。
4. 若外部调用已经开始但交付结果无法确认，命令进入 `deliveryUnknown`。
5. Worker 不再处理该命令；下一轮租约跳过它并选择其后的最早可发送命令。

## 运营 API

在管理员权限下提供发送队列 API：

- 分页列表：按机器人、群、状态和 UTC 时间范围筛选。
- 取消命令：只接受 `pending` 或 `retrying`，转换为 `cancelled`。
- 确认未知投递已处理：只接受 `deliveryUnknown`，转换为
  `deliveryUnknownResolved`。

变更请求必须携带并发版本；版本不匹配或状态已经变化时返回 `409 Conflict`。每次
操作写入统一管理审计，记录操作者、动作、命令 ID、原状态和新状态，不记录消息
正文、机器人标识或 WorkTool 消息 ID。

列表只返回运营所需字段：命令 ID、机器人名称、已登记群名称、状态、尝试次数、
创建时间、外部派发开始时间、完成时间、脱敏处理原因、并发版本和消息字符数。列表
不返回消息正文、群成员、机器人凭据或 WorkTool 原始响应。

## 前端页面

在运营区域新增“发送队列”页面：

- 顶部提供机器人、群、状态和时间范围筛选。
- 表格展示分页结果和中文状态说明。
- `pending/retrying` 显示“取消发送”，操作前使用 Element Plus 确认框。
- `deliveryUnknown` 显示“确认已处理”，明确提示该操作不代表发送成功，也不会重发。
- `leased/dispatching` 只读，等待 Worker 完成。
- 其他终态只读。
- 成功后刷新当前页；`409` 提示状态已变化并重新加载。

## 安全边界

- 不对 `deliveryUnknown` 自动重放。
- 不根据群名、消息正文或昵称推断是否已发送。
- 不删除或覆盖不确定命令的审计字段。
- 不在本次改动中新增运营重放 API。
- 不提供对 `leased/dispatching` 的强制取消。
- 不自动处理当前数据库已有的积压消息；管理员可在新页面逐条取消。

## 测试

增加 MySQL 集成回归测试：

1. 创建同一机器人的两条有序发送命令。
2. 租约第一条并将其标记为 `deliveryUnknown`。
3. 再次租约时应取得第二条命令。
4. 第一条保持 `deliveryUnknown`，没有再次增加尝试次数。

增加 API 集成测试：

- 分页和筛选返回真实、脱敏且有界的数据。
- 只有 `pending/retrying` 可取消。
- 只有 `deliveryUnknown` 可确认已处理。
- 并发版本冲突返回 `409`。
- 两种运营动作均写入统一管理审计。

增加前端组件测试：

- 状态对应正确的中文说明和可用操作。
- 确认框取消时不调用 API。
- 操作成功和 `409` 时刷新列表并显示明确提示。

现有并发租约、机器人发送门、限流、禁用机器人和 FIFO 测试必须继续通过。

## 验收标准

- 单条 `deliveryUnknown` 不会阻塞同一机器人后续 `pending` 命令。
- 不确定命令不会被 Worker 自动重发。
- 除 `deliveryUnknown` 外的活动状态继续维持同一机器人 FIFO。
- 管理员可以查看发送队列、取消尚未发送的命令并确认未知投递已处理。
- 前后端不会展示消息正文和 WorkTool 敏感标识。
- 不引入数据库结构或迁移变更。
