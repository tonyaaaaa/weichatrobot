# 群管理紧凑布局设计

## 背景

`/groups` 当前直接使用全局通用表单样式。全局样式将 `label` 设为块级元素，
并让 `input`、`select` 和 `textarea` 占满容器宽度；群规则组件没有专用的
Grid 或 Flex 布局。因此，规则类型、匹配内容、忽略大小写和删除操作被纵向铺开，
页面其他配置区也连续向下排列。

这不是业务流程要求，而是早期通用表单样式缺少页面级布局造成的结果。

## 目标

- 让整个 `/groups` 页面更紧凑、直观，充分利用桌面端横向空间。
- 突出匹配规则这一主要任务，同时保留标签、上下文和预览能力。
- 将每条规则压缩为容易扫描的一行。
- 在窄屏设备上保持可操作、无横向滚动。
- 保持现有 API、数据结构、匹配语义和保存行为不变。

## 非目标

- 不修改群匹配算法或规则优先级。
- 不修改群配置、标签、上下文或预览接口。
- 不引入新的组件库或全局设计系统。
- 不重构 `/groups/operations` 页面。

## 页面结构

页面采用“顶部识别区 + 主次双栏 + 底部保存区”。

### 顶部识别区

- 左侧显示“群管理”标题与简短说明。
- 右侧保留“新建群、成员和群信息操作”入口。
- 群配置 ID 输入框与“读取配置”按钮排列在同一行。
- 读取成功或失败的信息使用现有反馈机制，不改变数据流。

### 主次双栏

桌面端采用左宽右窄布局：

- 左栏承载“匹配规则”和“保存前预览”。
- 右栏承载“知识库标签”和“上下文策略”。
- 每个功能区使用独立面板，标题、说明和操作形成清晰层级。

左栏是主要工作区。右栏为辅助配置区，允许管理员在同一屏幕内核对标签和上下文，
但不与规则编辑争夺视觉焦点。

### 底部保存区

- “保存群配置”作为唯一主操作。
- 保存按钮与结果提示放在页面底部的明确操作区。
- 按钮禁用条件和现有提示内容保持不变。

## 匹配规则

包含规则与排除规则分别形成独立分区。

- “添加精确”“添加包含”“添加正则”操作归入各自分区标题栏。
- 每条规则在桌面端使用一行 Grid：
  1. 固定宽度的规则类型选择。
  2. 自动占据剩余空间的匹配内容输入框。
  3. 紧凑的“忽略大小写”复选项。
  4. 删除操作。
- 删除操作保留可读文字或无障碍名称，不能只依赖无标签图标。
- 输入、选择和按钮继续保持至少 44px 的可操作高度。

规则数据仍直接绑定现有 `includeRules` 和 `excludeRules`，添加、删除及编辑事件不变。

## 其他配置区

### 知识库标签

- 标签使用可换行的紧凑选择列表，而不是每个标签独占整行。
- 禁用标签和全局公开标签的文字说明保持不变。
- 禁用状态、绑定状态和复选逻辑保持不变。

### 上下文策略

- 数值与选择字段使用响应式两列网格。
- 字段标签、继承状态和有效值提示继续完整显示。
- “清空本群会话上下文”作为危险度较高的次要操作，与普通字段区分。

### 保存前预览

- 群名称输入区和“保存前预览”按钮在可用宽度内横向组合。
- 预览结果紧邻输入区显示。
- 文本框仍支持每行一个群名称，预览请求与结果结构不变。

## 响应式行为

- 页面可用宽度不小于约 900px 时显示主次双栏。
- 小于该宽度时切换为单栏，顺序为匹配规则、预览、知识库标签、上下文策略。
- 规则行在中等宽度下允许输入区占整行，其余控件保持紧凑排列。
- 手机宽度下控件按逻辑顺序换行，不出现横向滚动。
- 不通过降低字号或缩小点击区域换取紧凑度。

## 样式边界

- 页面和组件使用局部语义类覆盖全局表单规则。
- 不修改全局 `label`、`input`、`select`、`textarea` 行为，避免影响其他页面。
- 复用现有颜色、圆角、间距变量和焦点样式。
- 面板、网格与操作区只服务于 `/groups` 页面及其群配置子组件。

## 可访问性

- 保留现有表单标签和 `aria-label`。
- 键盘焦点顺序遵循视觉顺序。
- 所有交互控件保持可见焦点状态。
- 复选项文字可点击，删除操作具有明确名称。
- 状态提示继续使用 `aria-live`。

## 验证

- 现有群配置组件测试与端到端测试继续通过。
- 增加或调整组件测试，验证添加、编辑、删除和保存事件不受布局改变影响。
- 在桌面宽度和窄屏宽度分别进行浏览器截图检查。
- 确认桌面端单条规则为一行，窄屏无横向滚动。
- 确认全局样式未改变，其他后台页面布局不受影响。
