# 知识文档版本工作台设计

日期：2026-07-30
状态：已确认并实施
界面方案：A「版本工作台」

## 1. 背景

知识文档列表已经能够区分文档上传、消息审核入库和私聊直接入库，但当前详情
与分段页面仍以“上传文件后生成预览”为中心，导致自动来源存在三个问题：

- 已经写入 `KnowledgeChunk` 的批准内容无法通过预览接口展示，页面错误显示
  “共 0 段”。
- 私聊消息和消息审核的来源证据没有统一展示入口。
- 已批准版本必须只读，但页面没有版本化修订入口，运营人员无法修正内容后安全
  建立新索引。

本设计细化并替代
`2026-07-30-knowledge-document-list-redesign.md` 中第 7.5、7.6 节的详情页与
分段页安排。列表、筛选、停用和物理删除设计继续沿用原规格。

## 2. 设计原则

- 已批准、已索引和当前生效版本的正文不可原地修改。
- 内容修正必须创建新版本，并通过编辑、批准、索引、激活完整流程。
- 新版本索引成功前，机器人继续检索旧的生效版本。
- 原始消息是来源证据，不是可编辑正文。
- 知识标签没有独立保存动作；标签选择随索引或重新索引任务提交，并在索引成功
  后替换真实分段标签。
- 页面只展示真实后端能力，不提供没有 API 或没有状态闭环的按钮。
- MySQL 是文档、版本、来源、标签和任务状态的权威来源；Qdrant 是向量索引
  状态的独立来源。

## 3. 来源分类

版本工作台统一支持以下来源：

| `SourceKind` | 中文名称 | 正文维护方式 |
|---|---|---|
| `DocumentUpload` | 文档上传 | 上传文件创建新版本 |
| `ConversationReview` | 消息审核入库 | 查看来源并创建管理员修订 |
| `PrivateChatDirect` | 私聊直接入库 | 查看来源并创建管理员修订 |
| `AdministrationRevision` | 管理员修订 | 编辑当前修订预览，不覆盖旧版本 |
| `LegacyUnknown` 或未知值 | 历史数据 | 兼容展示，按实际持久化能力开放操作 |

管理员从工作台创建的版本使用 `AdministrationRevision`，同时设置：

- `ChangeKind = Correction`
- `SupersedesVersionId = 被修订版本 ID`
- `SourceActorDisplayName = 当前管理员显示名称`

这样列表能够准确显示“管理员修订”，而被替代版本仍保留原始的私聊或审核来源。
该来源使用现有字符串字段，不新增数据库列。

## 4. 页面信息架构

### 4.1 页面头部

头部显示：

- 文档标题。
- 当前生效版本。
- 来源中文名称。
- 文档状态和索引一致性。
- “刷新”按钮。
- “更多操作”菜单。

“更多操作”保留已有文档级能力：

- 停用文档。
- 提交物理删除。
- 文档上传来源允许上传新文件版本。

物理删除继续仅对管理员显示，并沿用现有乐观并发与异步清理语义。

### 4.2 主内容标签页

工作台左侧使用三个标签页：

1. **已入库内容**
   - 展示当前选择版本的真实 `KnowledgeChunk`。
   - 优先显示结构化问题、答案和同义问法；普通分段显示正文、页码及序号。
   - 已批准、已索引和生效版本只读。
2. **原始消息**
   - 展示来源成员、会话类型、接收时间和消息原文。
   - 只展示与当前版本有明确关联的消息。
   - 找不到历史关联时显示“历史来源证据不完整”，不得用文件名或昵称推断。
3. **版本历史**
   - 复用现有版本列表。
   - 显示来源、变更类型、被替代版本、标签、索引状态和创建时间。
   - 可切换查看任意历史版本，但历史版本始终只读。

### 4.3 右侧知识标签区

右侧展示当前版本真实绑定的知识标签并允许选择启用标签。

按钮规则：

- 标签没有变化：显示“重新索引当前版本”。
- 标签发生变化：显示“保存标签并重新索引”。
- 标签为空：按钮禁用并提示至少选择一个启用标签。
- 存在 `pending`、`leased`、`activating` 等进行中的索引任务：按钮禁用。
- 最近任务失败：额外显示“重试索引”，调用已有受控重试接口。

标签不会先单独写入数据库。任务成功完成时继续由现有索引服务替换
`KnowledgeChunkTag`，避免 MySQL 标签已经变化但 Qdrant 尚未更新的漂移状态。

### 4.4 内容维护区

只读生效版本显示：

- “创建修订版本”：没有未完成修订时显示。
- “继续编辑修订 vN”：已经存在当前文档的可编辑修订时显示。

创建修订后跳转到修订版本编辑页。编辑页沿用现有分段能力：

- 编辑。
- 拆分。
- 选择两个或更多连续分段合并。
- 删除分段。
- 批准分段。
- 批准后建立索引。

`AdministrationRevision` 已经从旧版本复制出预览内容，因此不显示“重新生成
预览”。重新生成只适用于有真实可解析文件来源的版本。

## 5. 按钮与状态机

### 5.1 创建修订版本

新增：

```http
POST /api/knowledge/documents/{documentId}/versions/{versionId}/revisions
```

请求：

```json
{
  "expectedDocumentStateVersion": 5
}
```

允许条件：

- 文档存在且未提交物理删除。
- 文档没有被停用。
- 来源版本属于当前文档。
- 来源版本具有至少一个批准分段。
- 当前文档不存在 `uploaded` 或 `preview` 状态的未完成管理员修订。

处理流程：

1. 对文档行进行并发保护并验证 `expectedDocumentStateVersion`。
2. 创建版本号递增的新 `KnowledgeDocumentVersion`。
3. 设置 `SourceKind = AdministrationRevision`、
   `ChangeKind = Correction` 和 `SupersedesVersionId`。
4. 把来源版本的批准分段复制为新版本的 `KnowledgeChunkPreview`。
5. 保留问题、答案、同义问法、页码、标题和表格等兼容元数据。
6. 新版本状态设为 `preview`，`PreviewRevision` 从 1 开始。
7. 写入统一管理审计。
8. 返回新版本 ID、版本号、预览修订号和编辑地址。

该操作不修改 `KnowledgeDocument.ActiveVersionId`，也不向 Qdrant 写入数据。

如果已经存在可编辑修订，接口返回稳定冲突契约及现有修订版本信息；前端切换为
“继续编辑修订 vN”，不重复创建版本。

### 5.2 批准与建立索引

修订版本继续复用现有分段批准 API。批准后：

1. 版本由 `preview` 进入 `approved`。
2. 用户选择知识标签并提交建立索引。
3. Worker 生成向量并写入暂存 collection。
4. MySQL 完成激活后，新版本成为 `ActiveVersionId`。
5. 旧版本退出生效状态但保留正文、来源证据和版本历史。
6. 后台按现有清理任务处理旧向量。

索引失败时旧版本继续生效，新版本保留失败任务并允许受控重试。

### 5.3 重新索引

已有接口继续使用：

```http
POST /api/knowledge/documents/{documentId}/versions/{versionId}/reindex
```

适用情况：

- 修改知识标签。
- Embedding 模型或维度发生变化。
- 检测到 Qdrant 漂移。
- 需要重建当前版本向量。

重新索引不创建新正文版本。

### 5.4 停用与物理删除

沿用现有接口和权限：

- 停用是可恢复的文档级状态；重新启用必须显式重新索引。
- 物理删除是管理员受控异步操作。
- 两者放入“更多操作”，不与版本内容按钮并列。

## 6. 只读内容与来源证据契约

新增：

```http
GET /api/knowledge/documents/{documentId}/versions/{versionId}/workbench
```

响应包含：

- 文档状态、状态版本和当前生效版本 ID。
- 当前版本完整来源、变更和索引摘要。
- 当前版本真实绑定标签。
- 批准分段的只读内容。
- 来源消息证据。
- 是否可以创建修订。
- 是否存在可继续编辑的修订版本。

来源消息规则：

- `PrivateChatDirect`：通过
  `KnowledgeDocumentVersion.SourceConversationMessageId` 读取消息。
- `ConversationReview`：新写入记录必须设置
  `SourceConversationMessageId`、`SourceActorDisplayName` 和可读的
  `StagedContent`。
- 历史 `ConversationReview` 数据缺少版本直接关联时，允许通过
  `KnowledgeCandidate.KnowledgeDocumentVersionId` 回查候选，再使用
  `SourceConversationMessageId` 或 `QuestionMessageId` 获取来源。
- `AdministrationRevision`：显示管理员修订信息，并通过
  `SupersedesVersionId` 跳转查看被修订版本的来源证据。
- 无可靠关联时返回空证据和明确原因，不制造来源文本。

响应不得包含回调令牌、机器人标识、稳定成员 ID 或其他敏感字段。

## 7. 前端页面拆分

### 7.1 文档管理详情

`KnowledgeDocumentManagementView` 负责：

- 文档级状态和危险操作。
- 来源概览。
- 版本历史。
- 文档上传来源的新文件版本上传。
- 进入选定版本工作台。

自动来源不显示文件上传区。

### 7.2 版本工作台

`DocumentDetailView` 调整为统一版本工作台：

- 读取新的 workbench 契约，不再用 preview API 展示已批准内容。
- 只读模式显示批准分段、来源证据和版本历史。
- `AdministrationRevision` 的 `preview` 状态进入可编辑模式。
- `DocumentUpload` 和兼容历史版本继续保留已有文件分段流程。
- 根据标签是否变化显示正确的索引按钮文案。
- 所有异步动作提供加载、成功、空状态、失败和并发冲突反馈。

## 8. 并发与失败处理

- 创建修订使用文档 `StateVersion` 乐观并发控制。
- 同一文档只允许一个未完成的管理员修订。
- 分段编辑继续使用 `PreviewRevision`。
- 索引任务进行中禁止重复提交。
- 创建修订冲突返回现有修订信息，不返回内部异常。
- 来源消息已清理或缺失时不阻塞正文查看。
- Qdrant 不可用时仍可查看 MySQL 中的正文、来源和版本历史。
- 管理审计只记录文档 ID、版本 ID、动作、结果和安全摘要。

## 9. Element Plus 与可用性

- 标签页、下拉菜单、选择器、消息框和标签组件必须同时引入逻辑与独立样式。
- 增加样式依赖回归测试。
- “创建修订版本”和危险操作使用 `ElMessageBox` 确认，不使用浏览器原生弹框。
- 键盘可以切换标签页、进入按钮和操作菜单。
- 窄屏下右侧栏移动到正文下方，按钮保持完整可见，不产生横向溢出。

## 10. 测试与验收

### 后端

- 私聊直接入库的 workbench 返回批准分段和原始消息。
- 消息审核新记录保存完整来源关联。
- 消息审核历史记录可通过候选回查来源。
- 无可靠来源时返回空证据而不是推断内容。
- 创建修订复制批准分段及兼容元数据。
- 创建修订不改变当前生效版本。
- 同一文档重复创建未完成修订返回冲突和现有版本。
- 文档状态版本冲突返回服务器当前状态。
- 停用或待删除文档不能创建修订。
- 修订批准并索引成功后才切换活动版本。
- 索引失败时旧版本继续生效。
- 标签只在索引完成阶段替换。
- 新接口在 MySQL 5.7 和受支持测试版本上执行。

### 前端

- 自动来源不再错误显示“共 0 段”。
- 已入库内容、原始消息和版本历史标签页显示真实数据。
- 已批准版本正文只读。
- 创建修订后进入新版本编辑页。
- 已存在修订时显示“继续编辑修订 vN”。
- 管理员修订可编辑、拆分、多段合并、删除和批准。
- 管理员修订不显示“重新生成预览”。
- 标签未变化显示“重新索引当前版本”。
- 标签变化显示“保存标签并重新索引”。
- 失败任务单独显示“重试索引”。
- 停用和物理删除位于“更多操作”且权限不变。
- Element Plus 样式依赖、桌面布局和窄屏布局通过视觉检查。

### 真实闭环

1. 私聊发送一条可入库知识并等待索引成功。
2. 从知识文档列表进入详情，查看原始消息和已入库问答。
3. 创建管理员修订并修改答案。
4. 批准修订并建立索引。
5. 验证新版本激活，旧版本保留但不再参与检索。
6. 私聊提问，验证机器人使用修订后的答案。

## 11. 非目标

- 不允许直接修改当前生效的 `KnowledgeChunk`。
- 不从 Qdrant 反向恢复正文或标签关系。
- 不改变文档停用、物理删除或旧向量清理语义。
- 不新增独立 `KnowledgeBase` 实体；“知识库”继续对应知识标签。
- 不处理无可靠 WorkTool 身份标识带来的成员身份映射问题。

## 12. 已确认决策

- 采用 A「版本工作台」。
- 已批准版本保持只读。
- 自动来源正文通过创建管理员修订进行修改。
- 原始消息作为只读来源证据展示。
- 标签修改与重新索引使用同一个提交动作。
- 内容未变时允许重新索引当前版本。
- 停用与物理删除保留在文档级“更多操作”。
