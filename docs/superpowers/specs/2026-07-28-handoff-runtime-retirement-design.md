# 人工转接运行功能退役设计

## 1. 背景

当前系统实现了人工转接状态机、客服分配、群级暂停、人工最终答案、知识候选、
管理 API 和前端操作页面。该实现假设系统能够把后台客服账号稳定映射到企业
微信成员，并能可靠确认接单人和最终答复人。

重新核对当前 WorkTool 官方能力后，系统只能通过显示名称向群发送消息并
`@` 指定名称。消息回调提供 `receivedName`、`groupName` 和
`groupRemark` 等显示字段，但没有可靠的企业微信内部成员 ID、客服接单状态
或最终处理归属。昵称改动、重名和备注差异都会破坏自动映射。

因此，现有人工转接代码虽然形成了内部状态流，但无法建立可靠的平台闭环。
本设计退役全部运行功能、API 和前端入口，同时保留历史数据库表和数据，等
新的长期记忆与知识学习链路稳定后，再单独设计物理删除迁移。

## 2. 已确认决策

- 彻底移除人工转接运行功能、API 和前端入口。
- 保留历史人工转接表、实体映射和已有数据。
- 历史数据只作为数据库留档，不提供新的操作入口。
- 新消息不得再创建、修改或依赖人工转接记录。
- 新知识候选不得再依赖人工转接记录。
- 后续物理删除历史表必须另立规格和迁移，不属于本期范围。

## 3. 目标

- 从入站消息处理链路中移除人工暂停、显式转人工和自动转人工。
- 从 API 路由中移除所有人工转接管理端点。
- 从前端移除人工转接页面、菜单、路由、客服选择和暂停策略。
- 停止把 `HumanAgent` 作为可分配、可授权的运行角色。
- 将无可靠证据和敏感问题处理改为不依赖人工转接的稳定回复。
- 保留历史表、外键和已有角色数据，不执行破坏性数据清理。
- 为独立的知识学习候选来源解除 `HandoffCase` 强依赖。

## 4. 非目标

- 不删除 `handoff_case`、`handoff_message`、`handoff_transition` 或相关历史
  数据。
- 不删除已有 `HumanAgent` 角色记录或已有用户角色关联。
- 不尝试通过昵称、群昵称、备注名或 WorkTool 显示字段修复客服身份映射。
- 不接入企业微信官方成员目录或客户群成员同步。
- 不提供历史人工转接恢复、重放、编辑或导出功能。
- 不在本期物理删除已不再使用的群人工客服和暂停策略列。

## 5. 运行行为

### 5.1 入站消息

`InboundMessageProcessor` 不再：

- 查询群或用户是否处于人工暂停状态。
- 捕获暂停期间消息。
- 识别“转人工”“人工客服”等显式转接词。
- 根据模型决策、敏感问题或连续失败创建人工转接。
- 在答案提交竞态中查询人工转接状态。
- 写入人工转接终态审计。

消息只经过群启用状态、规则匹配、上下文、知识检索、模型回答和发送队列。

### 5.2 信息不足

没有达到知识证据门槛时，系统返回固定的信息不足说明，不创建转接单、不暂停
AI，也不通知后台客服。

默认文案：

> 暂时没有找到可靠答案，请联系工作人员。

该文案继续由 `GroundedAnswer` 配置管理，但配置名称不得继续使用
`Handoff` 语义。

### 5.3 敏感问题

敏感问题不调用普通知识回答路径，返回固定安全说明：

> 该问题无法由机器人处理，请联系工作人员。

敏感问题不会创建人工转接，不会分配客服，也不会暂停后续消息。

### 5.4 “转人工”文本

“转人工”“人工客服”等文本不再具有控制语义，按普通问题进入知识检索。
没有可靠知识时返回信息不足说明。

## 6. 后端退役范围

### 6.1 API

停止注册以下路由及其子路由：

```text
/api/handoffs/**
```

退役后访问这些路径必须返回 `404`，不得返回伪造的空列表或
`feature-disabled` 成功响应。

### 6.2 应用服务

运行时不再注册或调用：

- `HandoffOrchestrator`
- `HandoffTriggerEvaluator`
- `HandoffService`
- `IHandoffStore`
- 与人工转接相关的暂停和恢复服务

为保留历史编译和后续物理清理依据，旧类型可以暂时保留在源码中，但不得由
API、Worker 或消息处理链路实例化。

### 6.3 Worker

Worker 不注册人工转接依赖，不扫描人工转接状态，不产生人工转接通知发送
命令。历史记录不得被后台任务自动恢复或更新。

### 6.4 群配置

群配置 API 不再接收、返回或修改：

- `HandoffPausePolicy`
- 群人工客服列表
- 默认人工客服
- 客服验证状态

数据库中已有列和关联记录保留。运行时忽略这些值。

### 6.5 用户角色

- 用户和角色管理 API 不再把 `HumanAgent` 返回为可分配角色。
- 新建、编辑用户时不能新增 `HumanAgent`。
- 已存在的 `HumanAgent` 角色关联保留，但不授予任何运行权限。
- 人工转接 API 移除后，历史角色不能访问任何对应操作。

## 7. 历史数据保留

以下表继续保留在 EF Core 模型和数据库中：

- `handoff_case`
- `handoff_message`
- `handoff_transition`
- 群人工客服关联表
- 其他只为历史人工转接服务的关系表

保留规则：

- 本期迁移不得删除表、列、索引或历史行。
- 不更新历史状态，不补写缺失字段，不重算负责人。
- 不通过新的后台 API 暴露人工转接操作。
- 现有外键继续保护历史关联。
- 后续物理删除前必须先完成数据保留期限和导出策略评估。

## 8. 知识候选解耦

现有 `KnowledgeCandidate` 由人工转接最终答案产生，并要求
`HandoffCaseId`。长期记忆项目将调整为：

- `HandoffCaseId` 可空，仅用于历史候选。
- 新增 `SourceType`。
- 新增可空的来源消息和来源记忆候选关联。
- 历史候选标记为 `HistoricalHandoff`。
- 自动整理产生的业务知识标记为 `MemoryExtraction`。
- 管理员从会话审计创建的候选标记为 `ManualCorrection`。

人工转接退役任务只解除运行依赖；具体新字段和新候选生成由长期记忆规格
负责。

## 9. 前端退役范围

删除或停止注册：

- “人工转接”菜单。
- 人工转接列表和详情路由。
- 人工转接 API 客户端及类型。
- 主动发起、分配、解决、恢复 AI 等按钮。
- 群配置中的人工客服选择区域。
- 群配置中的人工暂停范围。
- 用户页面中的 `HumanAgent` 角色选项。
- Dashboard 的待转接统计和入口。

前端不得保留不可操作的占位页面或“即将支持”提示。

## 10. 审计和兼容

- 新消息的会话审计不再生成 `Handoff` 决策。
- 会话审计 API 和前端不再返回或展示人工转接对象。
- 历史数据库记录保持原值。
- 历史人工转接数据只保留在数据库中，不通过应用 API 暴露。
- 最终删除历史审计字段前必须另立兼容性规格。

## 11. 错误处理

- 信息不足和敏感问题返回稳定、可配置的用户文案。
- 退役后的人工转接路径统一由路由层返回 `404`。
- 不允许因旧人工转接配置残留导致 Worker 启动失败。
- 不允许因历史 `HumanAgent` 用户存在导致登录或角色列表失败。
- 不允许后台任务修改或重放历史转接发送命令。

## 12. 数据迁移

本期不创建删除历史人工转接表的迁移。

如果知识候选解耦与退役在同一发布完成，只允许非破坏性变更：

- 将 `knowledge_candidate.HandoffCaseId` 改为可空。
- 增加知识候选来源字段。
- 保留现有外键，并允许可空关系。
- 为历史行回填 `SourceType=HistoricalHandoff`。

迁移必须兼容 MySQL 5.7，不依赖 MySQL 8 专属语法。

## 13. 测试策略

### 13.1 后端

- `/api/handoffs/**` 路由不存在。
- Worker 依赖容器不注册人工转接运行服务。
- “转人工”文本不创建 `handoff_case`。
- 信息不足不创建人工转接或暂停记录。
- 敏感问题不创建人工转接或发送客服通知。
- 普通知识问答和发送队列不受退役影响。
- 历史人工转接表在迁移后仍存在且行数不变。
- 历史 `HumanAgent` 角色不授予退役 API 权限。
- 新知识候选可以在没有 `HandoffCaseId` 的情况下创建和审核。

### 13.2 前端

- 菜单和路由不包含人工转接。
- 群配置不包含人工客服和暂停策略。
- 用户管理不包含 `HumanAgent` 选项。
- Dashboard 不包含待转接入口。
- 前端不再引用 `/api/handoffs/**`。

### 13.3 完成验证

- 运行服务端单元、合约和 MySQL 集成测试。
- 运行前端类型检查、组件测试和生产构建。
- 使用 `.local` 启动 API、Worker 和前端。
- 验证普通问答、信息不足、敏感问题和“转人工”文本行为。
- 验证历史表和数据未发生变化。
- 运行 `git diff --check` 和敏感信息检查。

## 14. 验收标准

- 系统没有任何可操作的人工转接入口。
- 新请求不会读取或写入人工转接运行状态。
- 退役 API 全部返回 `404`。
- 历史人工转接数据完整保留。
- 无可靠答案和敏感问题具有稳定、非转接式回复。
- 新知识学习链路不依赖人工转接。
